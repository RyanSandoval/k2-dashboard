Both ship prebuilt CSS on jsDelivr, so the "needs a build step" objection is dead for either of them. That was the thing I assumed would decide it and it did not.

What actually separates them

  • Basecoat themes entirely through oklch custom properties, so the locked graphite/blue palette drops in by overwriting about twelve values.
  • Franken UI is built on UIkit 3, which means inheriting UIkit conventions on top of Tailwind's. More surface area than this app needs.
  • Neither one is React, which matters because index.html is one file with no toolchain and a rewrite is not on the table.

The catch worth remembering: Tailwind v4 puts everything in @layer, and the 2,024 lines of CSS already in the app are unlayered. Unlayered wins the cascade. So old styles override Basecoat wherever they overlap — good for adopting it screen by screen, but it means the real work is retiring old CSS, not adding a library.

You are comparing these on the wrong axis. Both look fine. The question is which one you will still be able to theme in six months when the palette shifts again, and that is the one that keeps its colours in plain custom properties.

Worth flagging: you have picked a component library twice before and shipped neither, because both times the next step was "migrate the app" rather than "ship one screen." Convert Today, use it for a week, then decide about the rest.
